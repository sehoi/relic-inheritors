백로그 태스크 **하나**를 처음부터 끝까지 완료한다. 아래 순서를 그대로 따른다.
규칙은 `CLAUDE.md`와 `docs/AUTOMATION.md`에 있다. 어긋나면 절차가 아니라 규칙이 우선이다.

## 0. 준비
- `git checkout main && git pull --ff-only`
- 작업 트리가 더러우면 원인을 파악한다. 임의로 stash하거나 버리지 않는다.
- `npm run verify` — **main에서 이미 실패한다면 즉시 멈추고 사용자에게 보고한다.** 깨진 기반 위에 쌓지 않는다.

## 1. 태스크 선택
- `docs/BACKLOG.md`에서 `- [ ]` 중 최상단 항목을 고른다. 다음은 건너뛴다:
  - `- [!]` (BLOCKED)
  - **`⬅ 사람이 처리` 가 붙은 항목** — 에셋 조달, 계정·권한 설정, 세계관 확정처럼 루프가 할 수 없는 일이다. 건너뛰되 삭제하거나 체크하지 않는다. 사람이 처리하면 그때 사라진다.
  - 이런 항목 때문에 진행이 막혀서는 안 된다. 항상 그 아래에서 할 수 있는 일을 찾는다.
- 미완료 태스크가 3개 미만이면, 먼저 `docs/GDD.md`와 `docs/PROGRESS.md`를 읽고 다음 마일스톤 태스크 5개를 백로그에 추가한다 (각각 DoD 포함, 변경 파일 20개·추가 500줄 이내로 쪼갤 것).
- 고른 태스크가 그 크기를 넘길 것 같으면 쪼개서 백로그에 다시 넣고, **첫 조각만** 이번에 한다.

## 2. 브랜치
- `git checkout -b feat/<태스크ID>-<영문-슬러그>`

## 3. 구현
- `src/core/**`에 해당하는 로직이면 **실패하는 테스트를 먼저 쓴다.**
- 렌더링/UI는 스모크 테스트로 대체 가능하다.
- `CLAUDE.md`의 절대 규칙(core에 phaser 금지, Math.random 금지, 밸런스 상수 하드코딩 금지, 세이브 스키마 변경 시 마이그레이션 동반)을 지킨다.

## 4. 검증
- `npm run verify`
- 실패하면 고친다. **같은 태스크에서 2회 연속 실패하면** `docs/BACKLOG.md`의 해당 항목을 `- [!]`로 바꾸고 하위 줄에 사유를 적은 뒤, 브랜치를 버리고 이 이터레이션을 종료한다.

## 5. 실제 화면 확인
- dev 서버를 띄우고(`preview_start`) 내장 브라우저로 연다.
- 콘솔 에러가 0인지 확인한다. 에러가 있으면 4번으로 돌아간다.
- `npm run smoke` 가 `docs/screenshots/` 의 고정 이름 파일(`title.png`, `overworld.png` …)을 덮어쓴다.
  **태스크 ID를 파일명에 넣지 않는다** — 이터레이션마다 파일이 쌓이면 저장소가 부풀고 "지금 화면"이 어느 것인지 알 수 없게 된다. 변화는 git diff 가 보여준다.
- 새 씬을 추가했다면 스모크에 그 씬의 스크린샷도 추가한다.
- (씬이 아직 없는 M0 초반 태스크에는 해당 없음 — 건너뛰고 그 사실을 PR에 적는다.)

## 6. 커밋 · PR
- Conventional Commits로 커밋한다. 콘텐츠 추가만이면 `content:`.
- **루프 자신의 설정(`.claude/`)이나 프로세스 문서를 고쳐야 한다면 기능 PR에 섞지 말고 `chore/` 브랜치로 분리한다.** 기능 변경과 규칙 변경이 한 PR에 섞이면 나중에 어느 쪽을 되돌려야 하는지 알 수 없게 된다.
- PowerShell에서 `git commit -m` / `gh pr create --body` 에 여러 줄·따옴표를 직접 넘기면 인자가 깨진다. 반드시 파일로 넘긴다: `git commit -F <파일>`, `gh pr create --body-file <파일>`.
- `git push -u origin <브랜치>`
- `gh pr create` — 본문에 다음을 포함한다:
  - **무엇을 / 왜** (백로그 태스크 ID 인용)
  - **검증 방법** (어떤 테스트가 무엇을 보장하는지)
  - **스크린샷** (있으면)
  - **남은 리스크 / 다음 태스크에 넘기는 것**

## 7. 셀프 리뷰
- `/code-review` 를 실행한다.
- 지적사항 중 **실제 문제만** 수정한다. 취향 문제는 무시하고, 무시한 이유를 PR 코멘트에 한 줄 남긴다.
- 수정했으면 push.

## 8. 머지
- `gh pr checks` 로 CI가 초록인지 확인한다. 빨간 PR은 절대 머지하지 않는다.
- **PowerShell에는 `&&` 가 없다.** 명령을 줄바꿈으로 나열하면 앞이 실패해도 뒤가 실행된다 — 이건 게이트가 아니다. 반드시 종료 코드를 검사한다:
  ```powershell
  gh pr checks <번호> --watch --interval 20
  if ($?) { gh pr merge <번호> --squash --delete-branch } else { Write-Output "CI 실패 - 머지 중단" }
  ```
  (2026-08-04에 이 실수로 빨간 PR #4가 머지되어 main이 깨졌다.)
- CI 실패 시 원인을 고친다. 2회 연속 실패하면 PR을 draft로 내리고 백로그에 `- [!]` 표시 후 종료.
- 초록이면 `gh pr merge --squash --delete-branch`

## 9. 기록
- `git checkout main && git pull --ff-only`
- `docs/BACKLOG.md`의 해당 항목을 `- [x]`로 바꾼다.
- `docs/PROGRESS.md` **최상단에** 항목을 추가한다:
  ```md
  ### YYYY-MM-DD · T-0NN · <제목>
  - 한 일:
  - 알게 된 것:
  - 다음에 걸릴 것 같은 것:
  ```
- 아키텍처 판단을 내렸다면 `docs/DECISIONS.md`에 ADR을 추가한다.
- 이 기록만 담은 커밋을 main에 직접 하지 말고, `chore/log-<태스크ID>` 브랜치로 PR을 올려 머지한다.
