# 진행 저널

자율 루프가 이터레이션마다 **최상단에** 한 항목씩 추가한다.
위에서부터 읽으면 최근 진행 상황이 파악된다.

형식:

```md
### YYYY-MM-DD · T-0NN · <제목>
- 한 일:
- 알게 된 것:
- 다음에 걸릴 것 같은 것:
```

- 한 일: `packs` 도입, Kenney Tiny Town + Tiny Dungeon 등재, 고아 검사·CREDITS 대조를 팩까지 확장. 테스트 57 → 67개
- 사고 기록:
  - **CI가 빨간 PR #4를 머지했다.** PowerShell에 `&&` 가 없어서 `gh pr checks` 다음 줄의 `gh pr merge` 가 실패와 무관하게 실행됐다. main이 깨졌고 PR #5로 복구했다. `next-task.md` 8단계에 `if ($?)` 게이트를 명문화했다(PR #6).
  - 실패의 **원인 자체는 가드레일이 제대로 작동한 결과**였다. `git add -A` 가 작업 트리에 있던 Kenney zip 두 개를 쓸어담았고, T-007a에서 만든 고아 검사가 정확히 잡았다. 신호는 옳았고 내가 무시했다.
- 알게 된 것:
  - **팩 안의 항목은 `source` 를 생략하고 팩의 출처를 물려받는다.** 중복 기재를 강제하면 팩과 항목이 어긋날 여지가 생긴다(팩은 CC0인데 항목은 CC-BY라고 적히는 식).
  - `assets` 전체를 팩으로 선언하는 것과 팩 간 중첩을 금지했다. 전자는 고아 검사를 무력화하고, 후자는 소유가 모호해진다. 이 검사는 형식 검사보다 **먼저** 한다 — 걸리는 이유가 "경로 형식"이 아니라 "규칙의 근간"이라 메시지가 달라야 하기 때문이다.
  - Tiled의 타일셋 정의 파일이 `.tsx` 확장자를 쓴다. ESLint가 이를 TypeScript JSX로 파싱하려다 깨졌다. `assets/` 를 린트 대상에서 제외했다 — 어차피 우리 코드가 아니다.
- 다음에 걸릴 것 같은 것:
  - 팩 내부 파일은 용도가 기록되지 않는다. 실제로 쓰는 파일을 `entries` 에 올리는 규율이 무너지면 "어떤 시트를 쓰고 있었지"를 알 수 없게 된다.
  - T-007b(gid → 타일셋 좌표 매핑)의 선행 조건이 풀렸다. 다음 차례다.

### 2026-08-04 · T-007 · 타일맵 로딩과 렌더링
- 한 일: `core/world/tilemap.ts` (Tiled .tmj 파서·검증·타일 질의), `game/world/paintTilemap.ts` (플레이스홀더 렌더러), `src/data/maps/ruin-entrance.tmj` (30x16), OverworldScene 연결. 테스트 38 → 57개
- 알게 된 것:
  - **Tiled 스펙 중 쓰는 것만 받고 나머지는 명시적으로 거부했다.** 무한 맵·등각 투영·오브젝트 레이어·압축 data 를 조용히 무시하면 "왜 안 그려지지"를 나중에 디버깅하게 되는데, 그건 루프가 가장 못하는 일이다. 압축 data 는 거부하면서 "Tiled에서 CSV로 내보내라"까지 알려준다.
  - **`isSolid()` 는 맵 밖을 막힌 것으로 본다.** 경계 검사를 호출부마다 반복하면 언젠가 하나를 빠뜨린다. T-008 이동 로직이 이 계약에 기댄다.
  - 실제 맵 파일에 대한 테스트를 따로 뒀다 — 외곽이 전부 막혀 있는지, 스폰 지점이 막히지 않았는지, **ground(보이는 것)와 collision(막힌 것)이 어긋나지 않는지**. 마지막 것이 콘텐츠 작업에서 가장 자주 나는 버그다.
  - 등록되지 않은 gid 는 건너뛰지 않고 마젠타로 칠한다. 조용한 구멍보다 눈에 띄는 오류가 낫다.
  - `.tmj` 는 `?raw` 로 불러와 반드시 `parseTiledMap` 을 통과시킨다. 확장자가 `.json` 이었다면 Vite 가 자동 파싱해서 검증을 건너뛸 수 있었다.
- 프로세스 변경:
  - 스크린샷 파일명에서 태스크 ID를 뺐다 (`M0-title.png` → `title.png`). 이터레이션마다 파일이 쌓이면 저장소가 부풀고 "지금 화면"이 어느 것인지 알 수 없게 된다. `next-task.md` 5단계도 함께 고쳤다.
- 다음에 걸릴 것 같은 것:
  - 맵이 화면에 딱 맞아서(480x256 vs 480x270) 카메라 없이도 보인다. T-009에서 맵이 커지면 이 전제가 깨진다. OverworldScene 의 중앙 정렬 코드는 그때 카메라로 대체된다.
  - 백로그 최상단이 "에셋 필요"(사람 몫)라 건너뛰었다. `next-task.md` 에 사람 몫 항목을 건너뛰는 규칙이 명시돼 있지 않다 — 다음 이터레이션 전에 보완이 필요하다.

### 2026-08-04 · T-007a · 에셋 색인 체계
- 한 일: `assets/index.json` 스키마와 검증(`src/core/assets/`), Phaser 로더 브릿지(`src/game/assets/queueAssets.ts`), 저장소 정합성 테스트, `assets/README.md`·`CREDITS.md`. 테스트 12 → 38개
- 알게 된 것:
  - **런타임 의존성을 늘리지 않으려고 Zod 대신 손으로 검증기를 썼다.** CLAUDE.md 규칙 8이 "런타임 의존성 추가 시 사용자 확인"을 요구한다. 색인 검증 하나 때문에 승인을 기다리며 멈추는 것보다, 좁은 검증기를 직접 쓰는 편이 낫다고 판단했다. Zod 도입은 스키마가 여러 개로 늘어나는 T-012에서 정식으로 제안한다.
  - 검증기는 **첫 문제에서 멈추지 않고 전부 모아서 보고**한다. 하나 고치고 재실행하는 왕복이 루프에게는 통째로 한 이터레이션이다.
  - 없는 키를 조회하면 던지되, **에러 메시지에 다음에 할 일을 적었다** ("플레이스홀더로 진행하고 백로그에 추가하라"). 이 메시지는 사람보다 루프가 더 자주 읽는다.
  - 참조 스캐너가 자기 자신의 주석과 안내 문구를 오탐했다. 보증을 약화시키는 대신 정밀도를 올리고(공백 불허, 색인 자신 예외), **스캐너가 실제로 잡는지 증명하는 자체 테스트**를 붙였다. 발동하지 않는 가드레일은 없는 것과 같다.
- 다음에 걸릴 것 같은 것:
  - 에셋이 하나도 없어서 정합성 테스트 대부분이 자명하게 통과한다. 첫 에셋이 들어올 때 규칙이 실제로 물리는지 확인해야 한다.
  - 백로그에 "에셋 필요" 항목을 사람 몫으로 올려뒀다. 없어도 T-007·T-008은 플레이스홀더로 진행 가능하다.
