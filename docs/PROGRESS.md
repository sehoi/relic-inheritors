# 진행 저널

자율 루프가 이터레이션마다 **최상단에** 한 항목씩 추가한다.
위에서부터 읽으면 최근 진행 상황이 파악된다.

형식:

```md
### YYYY-MM-DD · T-0NN · <제목>
- 한 일:
- 알게 된 것:
- 다음에 걸릴 것 같은 것:
```

### 2026-08-04 · T-007a · 에셋 색인 체계
- 한 일: `assets/index.json` 스키마와 검증(`src/core/assets/`), Phaser 로더 브릿지(`src/game/assets/queueAssets.ts`), 저장소 정합성 테스트, `assets/README.md`·`CREDITS.md`. 테스트 12 → 38개
- 알게 된 것:
  - **런타임 의존성을 늘리지 않으려고 Zod 대신 손으로 검증기를 썼다.** CLAUDE.md 규칙 8이 "런타임 의존성 추가 시 사용자 확인"을 요구한다. 색인 검증 하나 때문에 승인을 기다리며 멈추는 것보다, 좁은 검증기를 직접 쓰는 편이 낫다고 판단했다. Zod 도입은 스키마가 여러 개로 늘어나는 T-012에서 정식으로 제안한다.
  - 검증기는 **첫 문제에서 멈추지 않고 전부 모아서 보고**한다. 하나 고치고 재실행하는 왕복이 루프에게는 통째로 한 이터레이션이다.
  - 없는 키를 조회하면 던지되, **에러 메시지에 다음에 할 일을 적었다** ("플레이스홀더로 진행하고 백로그에 추가하라"). 이 메시지는 사람보다 루프가 더 자주 읽는다.
  - 참조 스캐너가 자기 자신의 주석과 안내 문구를 오탐했다. 보증을 약화시키는 대신 정밀도를 올리고(공백 불허, 색인 자신 예외), **스캐너가 실제로 잡는지 증명하는 자체 테스트**를 붙였다. 발동하지 않는 가드레일은 없는 것과 같다.
- 다음에 걸릴 것 같은 것:
  - 에셋이 하나도 없어서 정합성 테스트 대부분이 자명하게 통과한다. 첫 에셋이 들어올 때 규칙이 실제로 물리는지 확인해야 한다.
  - 백로그에 "에셋 필요" 항목을 사람 몫으로 올려뒀다. 없어도 T-007·T-008은 플레이스홀더로 진행 가능하다.

### 2026-08-04 · T-001~T-006 · M0 부트스트랩
- 한 일: Vite + TS(strict) + Phaser 3 프로젝트 구성, `npm run verify` 파이프라인, 결정론적 RNG(mulberry32) + 12 테스트, Playwright 스모크, GitHub Actions CI, Boot→Title→Overworld 씬 골격
- 알게 된 것:
  - ADR-001/002를 문서로만 두지 않고 **ESLint 규칙으로 강제**했다. `src/core/**`의 phaser·window·document import 금지, 전 소스의 `Math.random()` 금지. 자율 루프는 문서를 어길 수 있지만 린트는 못 어긴다.
  - 씬 전환 검증을 스크린샷 픽셀 비교가 아니라 `body[data-scene]` 속성 질의로 했다 (`src/game/sceneMarker.ts`). 취약하지 않고 루프가 읽기 쉽다. **씬을 추가하면 반드시 `markScene()`을 호출해야 한다.**
  - npm 11이 install script를 기본 차단해서 esbuild postinstall 경고가 뜨지만, 플랫폼별 optional dependency로 바이너리가 들어와 빌드에는 지장이 없었다.
- 다음에 걸릴 것 같은 것:
  - 번들이 1.48MB(gzip 341KB)다. Phaser 전체를 싣고 있어서인데, 지금은 문제가 아니지만 M6 폴리시에서 커스텀 빌드나 코드 스플리팅을 검토해야 한다.
  - `npm run sim`은 아직 없다 (M3에서 생성). CLAUDE.md의 명령어 표에 (M3) 표시를 달아뒀다.
  - T-007a 에셋 색인이 다음 차례다. 에셋 팩이 아직 없으므로 빈 색인 + 플레이스홀더 규칙만 세우고 넘어간다.
