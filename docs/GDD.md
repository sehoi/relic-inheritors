# 게임 기획서 (GDD)

> 이 문서는 **백로그 생성의 근거**다. 루프는 백로그가 바닥나면 여기를 읽고 다음 태스크를 만든다.
> 여기 적히지 않은 것은 만들어지지 않는다. 방향을 바꾸려면 코드가 아니라 이 파일을 고친다.

## 1. 한 줄 요약

*(가제: 계승자 / Relic Inheritors)*

각인술 문명이 무너진 세계에서, 사람은 더 이상 스스로 마법을 쓰지 못한다.
힘은 오직 유적에 남은 **유물(Relic)** 을 통해서만 빌릴 수 있다.
유적을 파고, 유물을 회수하고, 그 힘에 잠식당하지 않으면서, 문명이 왜 무너졌는지를 밝히는
**2D 턴제 JRPG.**

## 2. 왜 이 컨셉인가 (설계 의도)

이 프로젝트는 자율 AI 루프가 개발한다. 그래서 **재미의 원천이 시스템과 데이터에 있어야 한다.**
손으로 쓴 서사에 재미가 걸려 있으면 루프가 아무리 돌아도 게임은 깊어지지 않는다.

유물 컨셉은 그 요구에 정확히 맞는다:

| 요구 | 유물 시스템이 답하는 방식 |
|---|---|
| 루프가 콘텐츠를 늘리면 게임이 깊어져야 한다 | 유물 1개 추가 = 8개 슬롯에 대한 조합 공간이 곱으로 증가 |
| 자동 검증이 가능해야 한다 | 조합별 승률·침식 곡선을 헤드리스 시뮬레이터로 측정 가능 |
| 긴 대본 없이 세계관이 전달되어야 한다 | 유물에 새겨진 기록으로 파편적 전달 — 유물이 곧 서사 단위 |
| 밸런스가 무너지면 감지되어야 한다 | "지배 전략 조합"의 존재 여부가 곧 회귀 테스트 |

## 3. 설계 축

| 축 | 결정 |
|---|---|
| 시점 | 탑다운 2D, 타일 기반 |
| 전투 | 턴제 커맨드, 프론트뷰(적만 표시) |
| 파티 | 최대 4인 · 각자 유물 슬롯 2개 = 총 8슬롯 |
| 진행 | 거점 마을 → 유적 탐사 → 귀환·정화 → 더 깊은 유적 (사이클형) |
| 목표 플레이타임 | 수직 슬라이스 40분 → 최종 6~8시간 |
| 난이도 | 중상. 갈아넣기보다 **조합 설계**로 돌파하게 만든다 |

## 4. 핵심 루프

```
거점(정화·장착·구매) → 유적 진입 → 전투로 침식 축적 → 유물 회수
        ▲                                                    │
        └──────── 침식이 한계에 닿기 전에 귀환 ─────────────────┘
                              │
                   회수한 유물로 조합 재설계 → 더 깊은 층
```

전투 하나하나의 승패보다 **"이 유물 조합으로 이 유적을 어디까지 버티는가"** 가 판단 단위다.

## 5. 유물 시스템 (이 게임의 중심)

### 5.1 유물 = 장비이자 스킬셋

캐릭터 고유 스킬은 1~2개뿐이다. **나머지 능력은 전부 유물에서 온다.**

```
Relic {
  id, name, tier(1~5), element, tags[]
  statMods:  { atk, def, mag, res, agi, ... }
  actives:   Skill[]        // 2~4개
  passive:   Passive        // 1개
  erosion:   number         // 스킬 사용 시 누적되는 침식 계수
  lore:      string         // 이 유물이 전하는 세계관 파편
}
```

캐릭터의 클래스가 고정되어 있지 않다. **어떤 유물을 주느냐가 곧 그 캐릭터의 역할이다.**
같은 캐릭터가 유물 배분에 따라 딜러도 힐러도 될 수 있다.

### 5.2 공명 (Resonance) — 조합이 의미를 갖는 지점

파티 전체의 장착 유물 태그 조합이 조건을 만족하면 파티 단위 효과가 발동한다.

```
Resonance {
  id, name
  condition: { tag: string, count: number }[]   // 예: 화염 2 + 바람 1
  effect: PartyEffect
}
```

유물이 늘어날수록 성립 가능한 공명 조합이 늘어난다. **루프가 `data/relics.ts`에 유물을 추가하는 것만으로 게임이 실제로 깊어지는 유일한 축이므로, 이 구조는 훼손하지 않는다.**

### 5.3 각인 성장 (Attunement) — 육성 대상이 캐릭터가 아니라 유물

- 유물은 사용할수록 숙련도가 오르고, 임계치에서 잠긴 액티브가 해금된다.
- 숙련도는 **유물에 귀속된다.** 캐릭터를 바꿔 끼워도 유지된다 → "계승"
- 캐릭터 레벨은 스탯 성장만 담당한다. 능력의 성장은 유물 쪽이다.

이 분리로 후반에 새 파티원이 합류해도 기존 자산이 죽지 않는다.

### 5.4 침식 (Erosion) — 리스크 축

- 강한 유물일수록 `erosion` 계수가 높다. 스킬을 쓸 때마다 캐릭터의 침식 수치가 오른다.
- 임계치 도달 시: 유물 **폭주**(1턴간 제어 불가, 무작위 대상 공격) 또는 **일시 봉인**(해당 전투 사용 불가)
- 침식은 전투 종료 후에도 남는다. 거점의 정화소에서 골드를 내고 씻어낸다.

이것이 "강한 유물을 그냥 계속 쓰면 되지 않나"를 막는 장치이자, 유적 탐사에 **자원 관리** 성격을 부여하는 축이다. 동시에 시뮬레이터로 측정할 값이 명확해진다.

### 5.5 자동 검증 대상 (루프가 지켜야 할 밸런스 불변식)

`npm run sim`이 다음을 측정하고, 위반 시 테스트가 실패한다:

| 불변식 | 판정 기준 (초기값, `data`에서 조정) |
|---|---|
| 지배 전략 부재 | **크기가 같은 조합끼리** 승률 1위와 5위의 차이가 25%p 이내 (ADR-013) |
| 유효 조합 다양성 | **크기가 같은 조합 중** 승률 55~85% 구간에 드는 것이 40% 이상 (ADR-013) |
| 침식 압박이 실재함 | 최적 플레이로도 유적 1회 완주 시 정화 1회 이상 필요 |
| 무의미한 유물 부재 | 어떤 유물도 "승률 상위 조합에서 채택률 5% 미만"이면 안 됨 |
| **필수 유물 부재** | 어떤 유물도 빼고 짠 최고 조합이 전체 최고보다 25%p 넘게 나쁘면 안 됨 — 위 항목의 반대쪽이다. 하한만 보면 "모두가 반드시 쓰는 유물"을 놓친다 (T-035) |
| 전투 길이 | 잡몹전 평균 3~6턴, 보스전 12~25턴 |
| **소모전** | 회복 없이 연속 15판: 시작 지역 전멸 10% 이하, 다음 층은 준비 없이 15% 이상 / 성장 후 15% 이하 — **단판 승률로는 이 게임의 난이도를 알 수 없다** |
| **유물 시스템 가동률** | 소모전 중 스킬을 하나라도 쓸 수 있는 상태로 시작하는 전투의 비율. 시작 지역 80% 이상, 깊은 층도 바닥 아래로 내려가지 않는다 — **MP가 마르면 남는 것은 기본 공격뿐이고, 그 구간에서 이 게임은 유물 게임이 아니다.** 승률만 보면 이 문제가 보이지 않는다 |
| **침식이 주 자원임** | 정화 없이 굴리면 유물이 봉인된 채 시작하는 전투가 실제로 나온다(하한). 거점에 들르면 눈에 띄게 줄어든다 — 앞은 "침식이 장식이 아니다", 뒤는 "거점이 값을 한다". 가동률 불변식과 짝을 이룬다 (저쪽은 MP 상한, 이쪽은 침식 하한) |
| **방어 스택 무적 부재** | 어떤 조합도 받는 피해를 원 공격력의 `PIERCE` 미만으로 낮출 수 없다 (공식이 보장하나, 회귀 방지를 위해 검사한다) |
| **방어 편향 부재** | 방어 특화 조합의 총 기여가 공격 특화 조합의 2배를 넘지 않음 — 넘으면 "일단 DEF부터"가 정답이 되어 조합 설계가 무의미해진다 |
| **레벨 간 난이도 붕괴 부재** | 보스전 승률의 레벨 간 최대-최소 차이가 45%p 이내 — 성장이 오히려 불리해지는 구간이 없어야 한다 (ADR-010) |

**이 표가 이 프로젝트에서 가장 중요한 부분이다.** 자율 루프가 밸런스를 망가뜨렸는지를 사람 없이 판정하는 유일한 수단이다.

두 가지가 이 표를 지킨다:

- **기구 검사** — 지배 전략과 사장된 유물을 일부러 심어놓고 불변식이 그걸 잡아내는지 확인한다.
  이게 없으면 초록이 "문제가 없다" 는 뜻인지 "아무것도 재지 않았다" 는 뜻인지 구분할 수 없다.
- **표본 수 고정** — 시드 40으로 재면 통과하고 300으로 재면 실패하는 일이 실제로 있었다 (ADR-013).
  판정과 `npm run sim` 리포트는 반드시 같은 표본을 쓴다.

## 6. 나머지 시스템

### 6.1 탐색
- 4방향 그리드 이동, 타일 충돌, 카메라 추적
- 맵 전환(계단·입구), NPC 상호작용, 대화창(페이지네이션·분기)
- 보물상자, 잠긴 문(키 아이템·플래그)
- 랜덤 인카운터: 걸음 수 + 지역별 인카운터 테이블
- **구역(Zone)**: 맵 한 장 안에서 장소를 나눈다 (ADR-011)
  - 구역마다 이름과 인카운터 발생 여부를 갖는다. `encounters: false` 인 곳이 **안전지대**다
  - 안전지대에서는 걸음 수를 세지 않는다 — 나가자마자 전투가 터지면 안전지대가 함정이 된다
  - **NPC 는 안전지대에 선다.** 말을 거는 도중에 습격당하면 안전해 보이는 곳이 안전하지 않다는 뜻이 된다
  - 화면 좌상단에 `맵 이름 · 구역 이름` 과 `안전`/`조우` 를 항상 띄운다. 안전지대는
    "아무 일도 일어나지 않음" 으로만 드러나므로, 표시가 없으면 플레이어는 운이 좋았던 것인지
    안전한 것인지 끝내 알 수 없다
  - 안전지대는 드물어야 한다. 흔해지면 탐색의 긴장이 사라진다 (콘텐츠 테스트가 비율을 지킨다)
- 유적 층마다 **회수 지점**(유물 발견) 1~2개

### 6.2 전투
- 턴 순서: AGI 정렬 + 소량 난수 흔들림 (시드 RNG 경유)
- 커맨드: 공격 / 유물 스킬 / 아이템 / 방어 / 도망
- 데미지 공식 (전부 `data`에 파라미터화 — 아래 상수는 초기값):

  ```
  raw    = ATK * power / 100
  base   = max(raw * PIERCE, raw - DEF * DEF_FACTOR, 1)     // PIERCE 0.2, DEF_FACTOR 0.5
  damage = base * variance(0.9~1.1) * elementMod * critMod  // critMod 1.5
  ```

  **`PIERCE` 관통 하한이 핵심이다** (ADR-009). 순수 감산형은 방어를 슬롯당 +2~6만 쌓아도
  받는 피해가 1로 고정돼 무적이 된다. 유물 8슬롯이 스탯을 보정하는 설계(ADR-004)에서
  그 수치는 평범한 값이라, 지배 전략이 구조적으로 발생한다.
  관통 하한은 방어의 상한을 65% 감소로 묶으면서 전투 길이는 그대로 유지한다.

- 스탯 성장 곡선은 아직 미확정이다. 선형을 가정해 검증했으며, 실제 값은 `data`에 두고
  시뮬레이터(§5.5)로 조정한다. 곡선을 바꿔도 위 공식의 결론은 달라지지 않는다.
- 속성: 화 / 수 / 뇌 / 지 / 무 — 상성표는 데이터
- 상태이상: 독, 마비, 수면, 침묵, 혼란. 각각 **커맨드 선택을 다른 방식으로 제약**한다 —
  피해만 주는 이상은 그냥 약한 공격이지 상태이상이 아니다.

  | 이상 | 제약 |
  |---|---|
  | 독 | 없음. 턴 종료마다 최대 HP 비율로 깎인다 |
  | 마비 | 확률적으로 턴을 잃는다 |
  | 수면 | 행동 불가. **피격하면 깨어난다** |
  | 침묵 | 스킬 봉인. 기본 공격은 된다 |
  | 혼란 | 확률적으로 대상이 무작위로 바뀐다 (아군 포함) |

  **적용 우선순위: 폭주 → 수면·마비 → 혼란 → 침묵.** 폭주는 제어 상실이라 무엇을 골랐든
  의미가 없으므로 가장 먼저다. 수면(확정)을 마비(확률)보다 먼저 보는 이유는, 순서를 뒤집으면
  잠든 액터가 마비 판정에 난수를 소비해 재현이 흔들리기 때문이다.

  같은 이상을 다시 걸면 **누적하지 않고 지속 턴을 긴 쪽으로 갱신**한다. 누적을 허용하면
  반복 시전으로 영구 봉인이 가능해지고 "수면 걸고 때리기"가 지배 전략이 된다.
- 적 AI: 가중치 기반 + HP 임계값 페이즈 전환
- MP 대신 **침식**이 주 자원. MP는 보조 자원으로 유지
  - 그러려면 MP 가 마르지 않아야 한다. **승리 시 쓰러뜨린 적 하나당 MP 1** 이 돌아온다 —
    이게 없으면 소모전 중반부터 기본 공격만 남고, 그 구간에서 이 게임은 유물 게임이 아니다
  - **HP 는 돌아오지 않는다.** 소모전의 축은 HP 로 남긴다 — 둘 다 돌아오면 소모전이 사라진다
- 무작위 폭은 `variance × critMod` = 0.9 ~ 1.65배로 묶는다. 속성 배율은 플레이어가 조합으로
  정하는 값이므로 무작위에 포함하지 않는다. 턴제 전략에서 운의 비중이 너무 커지면
  조합 설계라는 이 게임의 중심이 흐려진다.

### 6.3 성장
- 캐릭터 레벨 1~40 (스탯만), EXP 곡선은 데이터
  - **초반 곡선을 앞으로 몬다.** 첫 레벨업은 첫 전투에서 온다 — 처음 몇 판에서 레벨이 오르지
    않으면 플레이어는 자기가 나아지는지 알 수 없다
  - **레벨업은 완전 회복을 겸한다.** 유적에는 회복 수단이 없어(거점은 별개) HP·MP·침식이
    판을 넘어 쌓인다. "한 판만 더 버티면 오른다" 가 탐색을 이어갈 이유가 된다
  - 레벨은 저장하지 않는다. 누적 경험치에서 파생시킨다 — 둘 다 저장하면 언젠가 어긋난다
- 스탯: HP, MP, ATK, DEF, MAG, RES, AGI, LUK
- 유물 숙련도 0~5단계
- 아이템: 소모품(회복·부활·상태해제·정화석), 키 아이템

### 6.4 거점 UI
- 정화소(침식 제거), 상점, 여관, 유물 장착/공명 확인 화면
- 유물 화면에서 **현재 공명 성립 여부가 실시간으로 보여야 한다** (조합 설계가 게임의 핵심이므로)
  - 성립한 것만이 아니라 **아직 성립하지 않은 공명과 무엇이 모자란지도 함께** 띄운다.
    성립한 것만 보여주면 조합을 우연히 발견해야 하는데, 그건 핵심 시스템을 숨기는 일이다
  - 장착 화면은 **거점이 아니라 탐색 중 아무 때나** 열린다 (T-029). 유적 안에서 조합을 못 바꾸면
    조합이 게임의 중심이라는 말과 어긋난다

### 6.5 저장
- 슬롯 3개, localStorage
- 스키마 버전 + 마이그레이션 체인 (유물 숙련도·침식 상태 포함)

## 7. 아트 방향

**CC0 도트 에셋을 조달해 사용한다.** 루프는 그림을 그릴 수 없으므로 규칙을 명시한다.

- 해상도: 16x16 타일 기준, 정수 배율 스케일링 (픽셀 뭉개짐 방지)
- 출처: Kenney(kenney.nl) 등 CC0 팩 — 라이선스 검증된 것만
- **`assets/index.json`에 등재된 에셋만 사용한다.** 루프가 인터넷에서 임의로 내려받지 않는다.
- 필요한 에셋이 없으면: 단색 도형 플레이스홀더를 쓰고 `docs/BACKLOG.md`에 "에셋 필요: <용도>" 항목을 추가한다. 진행을 멈추지 않는다.
- `assets/CREDITS.md`에 출처·라이선스를 반드시 기록한다 (누락 시 CI 실패)

## 9. 마일스톤

| ID | 마일스톤 | 완료 조건 |
|---|---|---|
| **M0** | 부트스트랩 | `npm run dev`로 빈 씬이 뜨고, CI 초록, `npm run verify` 통과 |
